# 更新するときのきまり（使っている人の記録を消さないために）

このアプリの記録は、GitHub ではなく、使っている人それぞれのブラウザ（localStorage）に保存されています。
アプリのファイルを更新しても記録には触れませんが、次のことを守らないと、記録が読めなくなったり消えたりします。

## 変えてはいけないもの

- **公開アドレス**：`https://flawy0025.github.io/sns-kirokucho/`
  - リポジトリ名・GitHub のユーザー名を変えない。独自ドメインにしない。
  - 記録はアドレス（とくに `flawy0025.github.io` の部分）ごとに分かれて保存されるため、変えると記録が見えなくなり、ホーム画面のアイコンも開けなくなります。
- **保存の名前**：`sns-kirokucho.data.v1`（app.js の `DATA_KEY`）
  - 「v1」は名前の一部です。記録の形を変えても、この名前は変えません（版は `DATA_VERSION` で管理します）。

## 同じアドレスで別のアプリを公開するとき

`flawy0025.github.io` の下に公開するアプリは、すべて同じ保存場所を共有します。

- `sns-kirokucho.` で始まる名前を使わない。
- `localStorage.clear()` を使わない（このアプリの記録まで消えます）。

## 記録の形を変えるとき

項目を増やすだけなら、形は変えずに済みます（知らない項目も消さずに残す作りになっています）。
項目の名前や入れ物を変えるときは、次の順で行います。

1. app.js の `DATA_VERSION` を 1 上げる。
2. `MIGRATIONS` に「ひとつ前の版 → この版」の変換を足す。古い項目は消さずに残す。
3. `dev/fixtures/` に、新しい版の形の記録を `data-v<版>.json` として足す。古いものは消さない。
4. `dev/check.py` を通す。

変換の前には、元の記録が `sns-kirokucho.backup.v<番号>.<日時>` にそのまま控えられます。

## 公開する前に毎回

1. `python3 dev/check.py` を実行し、最後に「OK: 公開して大丈夫です。」と出ることを確かめる。
2. `sw.js` の `VERSION` を 1 つ上げる（新しい版を確実に届けるため）。
3. スマホの幅（400px 前後）で画面を確かめる。

## 記録を守る仕組み（app.js）

- **読めない記録**：消さずに `sns-kirokucho.rescue.<日時>` へ控えてから、空の手帖で始めます。画面に「控えを書き出す」ボタンが出ます。
- **新しい版の記録**：古い版のアプリ（キャッシュなど）で開いたときは、上書きしないよう保存を止め、読み込み直すよう案内します。
- **控えを作れないとき**：空き容量不足などで控えを作れないときも、保存を止めます。
- **すべての記録を消す**：記録と控えを消します。色の設定や他アプリの保存には触れません。

## ファイル

- `index.html`：画面と見た目（スタイルも中に入っています）
- `app.js`：アプリの動き（記録の保存は冒頭の storage の部分）
- `ocr-parse.js`：スクショの読み取り結果から数字を拾う処理
- `sw.js`：オフラインで開くための仕組み
- `dev/`：公開前のチェック（アプリ本体からは読み込まれません）
